1. Compare searching in an unsorted array and a sorted array.
answer:Searching is the process of locating a particular element in a collection of data. The time complexity depends on whether the array is sorted and which searching algorithm is used.In an unsorted array, the elements are not arranged in any particular order. Therefore, the program generally uses linear search, checking each element one by one until it finds the target or reaches the end of the array. In the worst case, all n elements must be checked, so the time complexity is \(O(n)\).In a sorted array, the elements are arranged in ascending or descending order. This order makes binary search possible. Binary search compares the target with the middle element and eliminates half of the remaining search range after each comparison. Its time complexity is \(O(\log n)\).For example, searching for 70 in a sorted array of 1,000 elements can take approximately 10 binary-search comparisons in the worst case, while linear search may need to examine all 1,000 elements.Conclusion: Linear search on an unsorted array takes \(O(n)\) time. A sorted array can be searched using binary search in \(O(\log n)\) time. A sorted array searched using linear search would still take \(O(n)\) time in the worst case.

2. Why is \(O(2n)\) simplified to \(O(n)\)?
Answer:
Big-O notation describes the rate at which an algorithm's resource requirements grow as the input size increases. It focuses on the dominant growth rate rather than exact operation counts or constant multipliers.Suppose an algorithm performs 2n operations for an input containing n elements. If the input size doubles, the number of operations also doubles. This is linear growth.Big-O notation ignores constant multipliers because they do not change the overall growth category. Therefore, \(O(2n)\) is simplified to \(O(n)\).
For example:- If \(n=10\), then \(2n=20\) operations.
- If \(n=100\), then \(2n=200\) operations.
- If \(n=1000\), then \(2n=2000\) operations.The number of operations grows proportionally to the input size. The factor of two changes the constant amount of work, not the growth rate Conclusion: \(O(2n)=O(n)\). Both represent linear time complexity.

3. How does traversal differ in linear and non-linear data structures?
Answer:
Traversal is the process of visiting elements in a data structure so that they can be processed, displayed, searched or modified.In a linear data structure, elements are organized sequentially. Examples include arrays, linked lists, stacks and queues. Except for the first and last elements, each element in a simple linear sequence has a predecessor and a successor. Traversal usually follows the sequence from one element to the next. For example, an array can be traversed using a loop from index 0 to index n - 1.In a non-linear data structure, elements are not arranged in a single sequence. Instead, they may form hierarchical or network-like relationships. Trees and graphs are common examples. A tree can have multiple child nodes, so traversal requires a defined strategy, such as preorder, inorder, postorder or level-order traversal. Graph traversal commonly uses depth-first search or breadth-first search to explore connected vertices while avoiding repeated visits.The fundamental difference is that linear traversal follows a sequential path, while non-linear traversal must account for branching relationships and, in graphs, possible cycles.conclusion: Linear structures are usually traversed sequentially. Non-linear structures require traversal algorithms suited to their relationships.
